## Product narrative (what Postsiva Unified feels like)

**Problem it addresses:** Teams and creators drown in **tabs**—LinkedIn company page vs personal, Instagram vs Threads, TikTok captions vs YouTube, different character limits and aspect ratios. Copy-paste errors and “wrong network tone” are common. Legacy schedulers often show **one generic preview** or a thin thumbnail, not how the post will **actually** read in each feed.

**Postsiva’s approach:**

1. **Workspace-centric identity** — Pick a workspace, connect OAuth accounts once, then switch **which connected profile/page/channel** is active from a header switcher (backed by unified user-profiles + token state). The UI knows whether you’re posting as a LinkedIn member vs org page, or which Facebook Page, etc.

2. **Unified composer with per-channel reality** — Write **shared or per-platform body copy**, attach media, then see **live mock previews** tuned to major networks (e.g. LinkedIn dark feed-style card, Instagram, X-style, etc.). The composer filters which networks are valid for **text vs image vs video vs carousel** so users don’t schedule impossible combinations.

3. **AI in the workflow, not only in a sidebar** — Workspace **FAB chat agent** for questions about connected accounts, posts, and comments; **AI assistant** flows in the post-scheduler area; optional **AI toolkit** states (e.g. generation shimmer) in the composer; **persona** settings to steer voice; server-side **content → image prompt → image** pipelines that adapt layout hints (e.g. infographic-style vs simple hero/banner) from post text.

4. **Automation-native surface area** — First-class **API keys**, documented **MCP server** (`https://mcp.postsiva.com/mcp`), Zapier/n8n patterns, Claude/Cursor/Raycast configs, and a **ChatGPT Custom GPT** path so LLMs can draft posts, pull stats, reply to comments, and generate images **with user consent and workspace context**—similar ambition to “headless social ops” but oriented to **modern agent protocols (MCP)** rather than only legacy REST integrations.

5. **Engagement loop** — **Inbox** for comment/conversation workflows; **dashboard** with profile hero, metrics bento, engagement chart, and recent posts fed by unified analytics/posts APIs—so scheduling is not the only story; **reacting and learning** from performance is in the same shell.

6. **Onboarding guardrail** — If a workspace has **no connected social accounts**, the app can block core routes and surface **Link platforms** (Connections modal / Settings → Connections) so empty states don’t masquerade as broken product.

## Workspace AI agent — what it can do

The **Postsiva assistant** is an **AI agent** bound to a **workspace**: it helps users manage **linked social accounts** from conversation—without expecting users to memorize internal IDs (tools resolve workspace context).

**Typical capabilities (tool-backed; exact names live in backend/MCP):**

- **Accounts:** List connected platforms, show profile basics, **OAuth connect** and **disconnect** links.
- **LinkedIn orgs & Facebook Pages:** List manageable company pages / orgs so users pick the right destination before publishing or scoping comments.
- **Content reading:** Recent **posts** across networks (with sensible limits and refresh rules), **scheduled queue**, **saved drafts**.
- **Analytics:** Workspace-wide and per-platform **aggregate** metrics (stored data) for “how am I doing” questions.
- **Comments:** Recent comments across posts, or comments on **one** post; **reply on-network** with the right platform and ids.
- **Drafting (does not auto-publish):** **Idea → multi-platform copy**, **copy → images** (`content_to_image`), **image URL → post copy**, **video URL → post copy**, **analyze image/video** (vision description vs marketing copy).
- **Publishing:** **Text / image / video** to **personal/default feeds** vs **Facebook Pages + LinkedIn org** (with overrides), including scheduling where supported—**confirm** destinations when needed.
- **Utilities:** Optional **web search** for facts relevant to social workflow; **clear chat memory** for this workspace channel when asked.

**Channels:** **Web FAB**, **WhatsApp**, **Instagram DM**, **Facebook / Messenger**—same agent role; **delivery** differs (e.g. rich markdown tables may be **web-only**; messaging channels stay plain and compact).

## WhatsApp integration

**Settings route:** `/settings/whatsapp` (under **Settings → Integrations** messaging area).

**Purpose:** Link a **phone number** to the workspace for **WhatsApp-related features** where the deployment supports them (e.g. workspace-scoped agent or ops workflows).

**UI behavior:** Users enter/save a **phone number** (+E.164 style); optional **Remove** with confirmation. The app may show a **`wa.me`** link when `NEXT_PUBLIC_WHATSAPP_BUSINESS_NUMBER` is configured (digits-only check in client)—used to open WhatsApp to the **business number**.

**Security note:** Treat workspace phone and **API keys** as sensitive; linking enables powerful agent actions for that workspace.

**Agent on WhatsApp:** After the business conversation is linked, users can **chat with the Postsiva workspace agent** in WhatsApp like other channels: list accounts, drafts, posts, comments, generate copy/images, post when confirmed, etc.—aligned with the capability list above.

## Instagram DM integration

**Settings route:** `/settings/instagram-dm`.

**Purpose:** Use the **same Postsiva workspace agent** from **Instagram Direct Messages** instead of only the web app.

**Setup (in-app copy):**

1. Open Instagram → **Direct messages**.  
2. Start a chat with the **official Postsiva Instagram account**.  
3. Send the workspace **API key** once in that conversation to verify and bind **this workspace** to that Instagram sender.  
4. After verification, use the agent from Instagram DM like any other chat.

**API key:** Created under **`/settings/api-keys`**. Treat like a password—anyone with the key can tie messaging to that workspace.

## MCP server & integrations catalog

Postsiva is built so **AI tools and automation** connect through **one MCP endpoint** plus **API keys**, not one-off scrapers.

### MCP (Model Context Protocol)

| Item | Value |
|------|--------|
| **Server URL** | `https://mcp.postsiva.com/mcp` |
| **Transport** | Streamable HTTP (as documented in Settings) |
| **Auth** | `Authorization: Bearer <API_KEY>` (API key from **`/settings/api-keys`**) |
| **Optional env override (frontend)** | `NEXT_PUBLIC_POSTSIVA_MCP_URL` |

**What MCP enables:** The same class of actions as the workspace agent—**connected accounts**, **posts**, **comments**, **replies**, **drafts**, **scheduling**, **unified content generation**, **image from text**, **analytics**, **OAuth links**, etc.—exposed as **tools** for Claude, Cursor, ChatGPT (where applicable), Zapier, n8n, and any MCP-compatible client.

### Integrations documented in-app (`/settings/integrations`)

Each integration includes **step-by-step setup** and often **example prompts**:

| Integration | Role |
|-------------|------|
| **Zapier** | **MCP Client by Zapier** — connect 5,000+ apps; Server URL + Bearer token; automate e.g. blog → post, sheets → drafts, scheduled summaries to Slack. |
| **MCP (generic)** | Any MCP-capable client: URL + `Authorization: Bearer API_KEY`. |
| **n8n** | MCP Client node — HTTP Streamable, Bearer auth, pick Postsiva tools in workflows. |
| **ChatGPT** | **Postsiva Social Media Manager** Custom GPT (external link in UI) — OAuth into workspace; actions respect plan limits. |
| **Claude** | **Desktop** (`claude_desktop_config.json` with `npx` + MCP URL + header) and **Claude Code** CLI (`claude mcp add …`). |
| **Cursor** | **Tools & MCP** — JSON `mcpServers.postsiva` with `url` + `authorization` header. |
| **Raycast** | Install Server flow — MCP URL + Bearer token. |
| **Perplexity** | Listed as **coming soon** in integrations data. |

**Messaging setup pages** (same Integrations studio): **WhatsApp** (`/settings/whatsapp`), **Instagram DM** (`/settings/instagram-dm`), **Facebook DM** (`/settings/facebook-dm`).

**API keys:** **`/settings/api-keys`** — create/revoke keys used for MCP, DM verification, and programmatic access.

## Supported networks & posting model (technical summary)

**Profile resolution:** Header rows from **`GET /unified/user-profiles/`** plus OAuth token presence; switching row changes who publishes and what dashboard cards reflect.

**Unified API platform slugs (examples):** `linkedin`, `facebook`, `instagram`, `threads`, `tiktok`, `youtube`, `pinterest`, `bluesky`.

**Post kind → eligible platforms (composer gating):**

- **Text:** linkedin, threads, facebook, bluesky  
- **Image:** linkedin, facebook, instagram, threads, tiktok, pinterest, bluesky  
- **Video / carousel:** linkedin, facebook, instagram, threads, tiktok, youtube, pinterest, bluesky  

**Important nuances:**

- **LinkedIn:** Personal profile **and** **organization pages** (separate selectable rows; org posting may need page/org identifiers in overrides).  
- **Facebook:** Product flows target **Pages**, not personal profiles (per in-app messaging).  
- **X vs Threads:** UI may show an X-style tile where the **unified pipeline uses Threads**—agents should not assume classic Twitter API without checking connection type.  
- **WhatsApp:** Used for **messaging/agent** integrations; not the same slug family as unified **public feed** posts above.
